## Часть 2. Операции с контейнером
- Прочитаем файл конфигурации _nginx.conf_ внутри контейнера docker с помощью команды _exec_.
    - `sudo docker exec admiring_lalande cat /etc/nginx/nginx.conf`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-16-07.png>)
- Создадим файл _nginx.conf_ на локальном компьютере.
    - `touch nginx.conf`
- Настроить его путь /status, чтобы возвращал страницу состояния сервера **nginx**
    ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-22-41.png>)
- Скопировать созданный файл _nginx.conf_ внутрь образа docker с помощью команды `docker cp` 
    - `sudo docker cp nginx.conf e1b8b1c3bbbb:/etc/nginx/`
      ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-25-00.png>) 
- Перезапустить **nginx** внутри образа docker с помощью _exec_.
    - `sudo docker exec e1b8b1c3bbbb nginx -s reload`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-25-59.png>)
- Убедиться, что _localhost:80/status_ возввращает страницу состояния сервера **nginx** 
    ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-26-24.png>)
- Экспортируйте контейнер в файл _container.tar_ с помощью команды _export_.
    - `sudo docker export e1b8b1c3bbbb > container.tar`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-28-07.png>)
- Остоновим контейнер.
    - `sudo docker stop e1b8b1c3bbbb`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-29-11.png>)
- Удалите изображение с помощью `docker rmi [image_id|repository]` предварительно не удаляя контейнер.
    - `sudo docker rmi --force a72860cb95fd`
       ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-33-02.png>) 
- Удаляем остановленный контейнер.
    - `sudo docker rm e1b8b1c3bbbb`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 17-39-00.png>)
- Ипортируем контейнер обратно с помощью команды _import_.
    - `sudo docker import -c 'CMD ["nginx", "-g", "daemon off;"]' ./container.tar nginx`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 18-00-38.png>)
- Запускаем импортируемый контейнер.
    - `sudo docker run -d -p 80:80 -p 443:443 nginx1`
        ![](<fot/Part 2/Снимок экрана от 2024-08-12 18-01-30.png>)
- Убидиться, что _localhost:80/status_ возвращает страницу состояния сервера **nginx**
    ![](<fot/Part 2/Снимок экрана от 2024-08-12 18-03-02.png>)
## Часть 3 Мини Веб-сервер
- Установим библиотеку
    - `sudo apt-get install libfcgi-dev`
- Напишим мини-сервер на **С** и **FastCGI**, который будет возвращать простую страницу с надписью `Hello World!`.
    ![](<fot/Part 3/Снимок экрана от 2024-08-14 16-13-34.png>)
- `gcc server.c -lfcgi -o server`
    ![](<fot/Part 3/Снимок экрана от 2024-08-14 16-17-37.png>)
- Запустите написанный мини-сервер через spawn-fchi на порту 8080.
    - `sudo spawn-fcgi -p 8080 ./server`
        ![](<fot/Part 3/Снимок экрана от 2024-08-14 16-46-53.png>)
- Напишем свой собственный _nginx.conf_, который будет проксировать все запросы с порта 81 на 127.0.0.1:8080.
        ![](<fot/Part 3/Снимок экрана от 2024-08-14 19-35-56.png>)
  - Запустим контейнер на порте 81 `sudo docker run -d -p 81:81 nginx1`
  - Копируем туда файлы `sudo docker cp nginx.conf sleepy_mclaren:/etc/nginx/` и `sudo docker cp server.c sleepy_mclaren/home`
  - Запускаем bash в контейнере `sudo docker exec -it bsleepy_mclaren bash`
  - Устанавливаем библиотеки и утилиты из контейнера
    - `apt install gcc`
    - `apt install libfcgi-dev`
    - `apt install spawn-fcgi`
  -  Компилируем сервер в контейнере `gcc server.c -lfcgi -o server`
  - Запускаем `spawn-fcgi -p 8080 ./server`
  - Перезагружаем nginx `nginx -s reload`
- Проверяем, что браузер на _localhost:81_ возращает страницу, которую была написана
![](<fot/Part 3/Снимок экрана от 2024-08-14 19-28-02.png>) ![](<fot/Part 3/Снимок экрана от 2024-08-14 19-33-29.png>)

## Часть 4. Собственный docker
- # Напишем собственный образ docker, который:
#### 1)Создает исходные тексты мини-сервена на FastCGI из # Части 3;
#### 2)Запустить его на порту 8080;
#### 3)Копирует внутри образа написанный ./nginx/nginx.conf;
#### 4)Запускает nginx.

![](<fot/Part 4/Снимок экрана от 2024-08-16 20-12-09.png>)
- Создаем созданный образ docker с помощью `docker build`, указав имя и тег.
- `sudo docker build -t my_docker:latest`.
- Проверяем с помощью `docker images`, что все построено правильно.
    - `sudo docker images`
    ![](<fot/Part 4/Снимок экрана от 2024-08-16 20-21-23.png>)
- Запустите созданный образ docker, сопоставив порт 81 с 80 на локальном компьютере и сопоставив папку ./nginx внутри контейнера с адресом, по которому расположены файлы конфигурации nginx (см. Часть 2)
    - `sudo docker run -it -p 80:81 -v ./nginx.conf:/etc/nginx/nginx.conf --name server_container my_docker`
- Эта команда Docker запустит контейнер, пробросив порт 81 внутри контейнера на порт 80 на машине. Она также подключит файл конфигурации nginx.conf к контейнеру.
- Убидимся, что страница написанного мини-сервера доступна на localhost:80.
    ![](<fot/Part 4/Снимок экрана от 2024-08-16 20-31-14.png>)
- Добавить проксирование страницы /status в ./nginx/nginx.conf, чтобы возврашал состояние сервера **nginx**.
    ![](<fot/Part 4/Снимок экрана от 2024-08-16 20-32-40.png>)
- Перезапустим образ docker. 
    - `sudo docker restar server_container
        ![](<fot/Part 4/Снимок экрана от 2024-08-16 20-33-23.png>)
- Убедитесь, что _localhost: 80/status_ теперь возвращает страницу со статусом **nginx**.
        ![](<fot/Part 4/Снимок экрана от 2024-08-16 20-33-58.png>)
